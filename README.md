## 🎯 문제 정의

고령층(Active Senior)의 자산 규모는 빠르게 증가하지만, 격차도 함께 커지고 있다.

| 지표 | 수치 |
|---|---|
| 60대 이상 자산 5년 성장률 (2017→2022) | **+87%** |
| 상위 20% vs 하위 20% 자산 격차 | **75.3배** |
| 은퇴기 금융 니즈 영역 | 저축·상속·증여·연금·자산관리 등 복잡화 |

**핵심 문제**
1. 개별 자산관리 부재 → 자산 부족 사각지대 발생
2. 표준화된 금융상품 추천이 고령층 개별 상황(소득 · 신용 · 가족구성)을 반영하지 못함
3. 위험군 조기 탐지를 통한 예방적 관리 부재

→ **고령층 재무 특성 기반의 자산 부족 위험군 예측 + 맞춤형 금융상품 추천 모델 개발**

## 🏗️ 파이프라인

```
사용자 재무 입력
       │
       ▼
┌─────────────────────┐
│ ① TabNet 위험군 분류 │  → 고/중/저위험 페르소나 정의
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ ② 룰 기반 필터링      │  → 나이·소득·신용등급으로 부적합 상품 제거
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ ③ FAISS 유사도 추천  │  → 사용자/상품 임베딩 L2 검색 → Top-3
└─────────────────────┘
```

### 단계별 설명

| 단계 | 역할 | 기술 | 산출물 |
|---|---|---|---|
| ① 위험군 분류 | 재무 특성 → 고/중/저위험 페르소나 분류 | TabNet (표형 데이터 attention 기반 분류) | `tabnet_model.pkl` |
| ② 제약 필터링 | 금융 규제·가입 조건 반영해 부적합 상품 제거 | 룰 기반 비즈니스 로직 | `reco_config.pkl` |
| ③ 유사도 추천 | 사용자·상품 임베딩 유사도 기반 Top-3 추천 | FAISS L2 인덱스 | `faiss_index.idx`, `faiss_products.idx` |

## 💡 주요 기술적 의사결정

### 왜 TabNet인가?
- **해석 가능성**: 금융 도메인 특성상 모델 결정 근거를 설명할 수 있어야 함 → TabNet의 attention mask로 어떤 피처가 분류에 영향을 줬는지 추적 가능
- **표형 데이터 적합성**: 카테고리 변수(신용등급·연금 종류) 자동 임베딩 → 별도 원-핫 인코딩 불필요
- **비교 검토**: XGBoost · RandomForest 베이스라인 대비 정확도·설명력 모두 우위 확인

### 왜 FAISS인가?
- **확장성**: 사용자 수와 상품 수가 늘어나도 ms 단위 검색 가능 (브루트포스 코사인 대비)
- **임베딩 친화적**: TabNet 분류 결과의 위험군 임베딩을 그대로 검색 키로 활용 가능
- **대안 검토**: scikit-learn `NearestNeighbors`는 데이터 양 증가 시 한계 → 운영 환경 고려해 FAISS 채택

### 왜 룰 기반 필터링을 중간에 끼웠나?
- 금융상품에는 **법적 가입 제약**(연령 하한, 신용등급 하한, 소득 요건)이 존재 → 이를 ML 모델에만 맡기면 위반 가능성
- "적합도 높음 + 가입 가능" 두 조건을 분리해 책임 명확화
